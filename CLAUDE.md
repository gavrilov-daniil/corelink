## Жёсткие правила

1. **Идентичность клиента переносится дословно.** `short_uuid`, `vless_uuid`, hwid, URL подписки байт-в-байт (`panel.gavy.shop` + `/auto/<uuid>` + `/api/sub/<id>` + те же заголовки). Reality-ключи **импортировать, не регенерировать**: смена `pbk` рвёт всех клиентов канала.
2. **Ядро сети воспроизводится 1:1** — VARIANTS, loopback-failover, geo-free split. `geoip:`/`geosite:` в клиентском конфиге — никогда (в Happ нет geo-баз, валит XrayCore).
3. **Секреты только в `.env` и vault.** В коде, репозитории, доках и чате — не светить. Репозиторий **публичный**.
4. **Записи в БД идемпотентны**, барьер — уникальный индекс, а не проверка в коде. Деньги — ledger-first: баланс = агрегат по append-only транзакциям.
5. **Никаких прямых HTTP-вызовов** из контроллеров и роут-хендлеров: очередь + retry + timeout + idempotency key.
6. **Миграции:** `when` в `_journal.json` брать как `максимум + 10000`. Drizzle МОЛЧА пропускает миграцию с меньшим таймстемпом, рапортуя об успехе (`packages/db/drizzle/meta/README.md`).
7. **После изменений в схеме, генераторах конфигов или выдаче подписки** — прогон тестов целиком, не только затронутого пакета.

## Локальный запуск

```bash
pnpm install && pnpm build
DATABASE_URL="postgres://vpn:vpn@localhost:5442/vpn_platform" node packages/db/dist/migrate.js
```

core — `node apps/core/dist/main.js`, админка — `pnpm --filter @corelink/admin dev` (порт 3200, проксирует на 3100).

- Порты: Postgres **5442**, Redis **6392** (стандартные заняты другими проектами хоста).
- core **обязан** запускаться из tsc-сборки. Через tsx падает NestJS DI: esbuild не эмитит `emitDecoratorMetadata`.
- Тесты против живого Redis включаются `TEST_REDIS_URL`; без неё Redis-блоки скипаются, и часть дефектов не ловится.
- `DEFAULT_ORG_ID` в dev-базе — дефолтный `00000000-…-0001`. В таблице `node` есть осиротевшие строки из тестов с другим org — брать org оттуда нельзя.

## Что не проверено на живой ноде

Гейт перед переключением боевого трафика — brownfield-импорт Reality-ключа (режим `import` с сохранением `pbk`): на живой ноде не проверялся.

Проверено 26.09.2026 на нодах тест-стенда (de-1, de1-exit, режим `generate`): рестарт Xray агентом с новым конфигом и подставленным ключом (пересобранный desired-state применён за ~1 мин, трафик пошёл с новым uuid) и чтение статистики из настоящего Xray (окна по 30 с в `traffic_sample`, `traffic_daily` сходится с ними до байта). Сверки байтов с реальностью не было — «учёт трафика точен» утверждать нельзя, `used_traffic` и `subscription-userinfo` достоверными пока не считать.
